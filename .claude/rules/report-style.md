# Rule: Report style and tone

All written analytical outputs (performance summaries, transfer pitches,
player comparisons, SkillCorner reports) must follow these standards.

## Report structure

Every written output follows this layout:

```
PLAYER PROFILE
[Name | Position | Club | League | Age | Sample: X mins / Y matches]

OVERVIEW
[2-3 sentence summary of player profile and role]

KEY METRICS
[Structured table or clearly formatted metric breakdown]

ANALYSIS
[Substantive written assessment — technical, direct, no filler]

COMPARISON CONTEXT
[State peer group, sample size, any multipliers applied]

SUMMARY / RECOMMENDATION
[Tailored to the audience]
```

## Audience — always confirm before writing

**internal**: Candid, full analytical depth. Flag concerns directly.
Can reference specific percentile weaknesses without softening.

**player**: Honest and constructive. Development-focused. Accessible language
but do not remove analytical depth. No vague praise.

**club**: Polished and confident. Leads with player profile, supports with
data, closes with a fit argument tailored to the club's context.

## Tone rules

- Technical, direct, professional
- Every claim grounded in data provided
- No filler sentences
- No vague praise ("a dynamic presence", "works hard")
- No em dashes in narrative prose
- Avoid passive constructions where active is cleaner
- Accessible enough for a non-data audience without stripping depth

## Metric expression in prose

- Lead with per-90 figure, include raw in brackets: "0.42 goals per 90 (8 goals)"
- State sample size in the player profile line, not buried in the analysis
- If a percentile is referenced in prose, include peer group context:
  "placing him in the 78th percentile among League One central defenders (n=62)"

## Comparison context block

Always state:
- Peer group definition (position, league, minimum minutes)
- Number of players in peer group
- Any cross-league multiplier applied and what it was

## Transfer pitch specifics

1. Open with player profile and headline stats
2. Support every claim with data
3. Close with a fit argument — reference the club's context if provided
4. Keep it concise — a club reader should not need to scroll past essential info
5. Confidence is required; hedging reads as uncertainty in the player's quality
